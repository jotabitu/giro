# T-182 · Tela de Configurações · frontend → orquestrador, qa

**O que foi feito:** `/admin/configuracoes` com a ordem e o visual de `Config-Desktop` e `Config-Mobile`: cabeçalho "Administração · Configurações" (com a frase de apoio no desktop e a seta de voltar para Mais no celular), um cartão por item de `cartoes` na ordem da API, com `titulo` e `resumo` como vêm, ícone e link pela tabela "Rotas dos cartões". Cartão que a API não manda não aparece (sem buraco). A faixa da implantação só aparece no desktop e só quando `implantacao` não é `null`; o botão só quando `acao` vem (`nova_locacao` leva a `/locacoes/nova`; `implantacao` abre `/implantacao`, porque o assistente ainda não tem contrato por passo). Quem não é administrador vê o aviso e a tela não chama a API. Estados de carregando e erro tratados.
**Onde:** `frontend/src/components/admin/Configuracoes.tsx`, `app/(empresa)/admin/configuracoes/page.tsx`, `lib/configuracoes.ts` (chave para rota e ícone), `lib/api/{configuracoes,tipos-configuracoes}.ts`, fixture `testes/falsos/falso-configuracoes.ts`, `components/admin/Configuracoes.test.tsx`. O falso da navegação passou o item `config` para o módulo `configuracoes` (e `TODOS_OS_MODULOS` ganhou a chave), como no backend.
**Contrato:** `GET /api/configuracoes/` (`docs/api/configuracoes.md`). O guarda de rota é o do menu (T-136): o item `config` já abre `/admin/configuracoes` em `rotaPermitida`.
**Regras cobertas:** USR-05 (cartão sem tela não vem), IMP-01 (faixa some com a implantação concluída). Testes: seed com 8 cartões e sem faixa, cartão ausente, faixa 6 de 10 sem botão e só no desktop, `acao` `nova_locacao`, perfil sem acesso.
**Cliente tipado:** `npm run api:gerar` regenerou `schema.d.ts` (ignorado pelo git) a partir do `openapi.yaml` da T-181.
**Verificação:** `npm run lint`, `npm run typecheck`, `npm test` (454 testes) e `npm run build` limpos. Não conferi no navegador (precisa do compose com o backend da T-181): olhar 1440 px e 390 px com a Mariana, e com a empresa em implantação para ver a faixa.
